# Process Redesign and Validation

## Purpose

Use this skill to design To-Be process options, compare them, validate them with stakeholders, and approve a process baseline.

## Operating Procedure

1. Start from confirmed As-Is analysis and known constraints.
2. Identify improvement opportunities and target outcomes.
3. Generate alternative To-Be options when the decision is non-trivial.
4. For each option, assess impact, feasibility, risks, dependencies, and stakeholder implications.
5. Prefer standardization before automation when process variation is uncontrolled.
6. Avoid automation recommendations when root causes are unresolved.
7. Select a recommended To-Be or define what evidence is needed to choose.
8. Validate the proposed model with process owners and affected stakeholders.
9. Collect corrections and version the model.
10. Approve the baseline only when evidence coverage, stakeholder coverage, and unresolved risks are acceptable.

## Validation Checks

- evidence coverage
- stakeholder coverage
- contradiction resolution
- process owner review
- exception handling
- control and compliance implications
- system feasibility
- implementation dependencies
- baseline approval status

## Rules

- Do not present a To-Be as final before stakeholder validation.
- Do not hide tradeoffs between options.
- Do not optimize locally if it damages the end-to-end process.
- Do not propose technology as the default answer.
- Keep unresolved assumptions visible until validated.

## Output Pattern

Return:

- redesign objective
- constraints
- To-Be options
- impact and feasibility comparison
- recommendation
- validation plan
- unresolved assumptions
- approval or readiness status
